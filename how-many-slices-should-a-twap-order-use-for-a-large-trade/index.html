How many slices should a TWAP order use for a large trade?

How many slices should a TWAP order use for a large crypto trade? Start with a tolerable slice size, then check the interval and execution costs.

By The Coin Wire EditorialNov 25, 2026 · 08:06 UTC4 min read

There is no universal slice count for a large Fraxswap TWAP order: choose a slice size that fits the pool’s liquidity, then divide the order into evenly spaced portions.

More slices make each portion smaller, which can limit the market impact of each trade, but very frequent or tiny executions may be inefficient once fees and gas are considered. The practical count depends on the order size, available liquidity, how long the order can run, and execution costs.

A TWAP and VWAP comparison can clarify how trade pacing differs; Fraxswap TWAP and VWAP trade pacing covers that distinction. On the AMM, pool liquidity helps determine what slice size is practical.

Choose a tolerable slice size before choosing the count

For a regular TWAP, a slice is one portion of the total order, and its interval is the time between portions. Divide the order value by the number of slices to find each slice’s value; divide the total duration by the count to find the interval.

Take a $120,000 trade planned over six hours. At 12 slices, each portion is $10,000 and executes every 30 minutes. At 24 slices, each is $5,000 and executes every 15 minutes. The higher count halves the portion size and the interval.

Those calculations describe a schedule, not a promise about the final price. A smaller portion may have less market impact when it trades, but the best schedule also depends on the pool and the costs of executing it. Increasing the count without checking those costs can add complexity without making the trade meaningfully better.

Compare two versions of that same $120,000, six-hour order. Suppose a deep pool can accommodate $10,000 portions within the trader’s chosen impact tolerance: 12 slices fit that assumption. Suppose a thinner pool makes $5,000 the tolerable portion: the schedule needs 24 slices. The order and duration stay the same; the liquidity assumption changes, so the count changes. These thresholds are illustrative—the trader must assess the actual pool.

A practical selection rule is to estimate the largest per-slice value the available liquidity can handle within your tolerance, then divide the total order by that value and round up to a whole number. Next, check the resulting interval against the execution method and its costs. If the interval becomes impractical, revisit the duration or the tolerated slice size rather than assuming that more slices are automatically safer.

A Fraxswap TWAMM does not submit that many separate swaps

A slice count is a planning model for pacing an order; a Fraxswap TWAMM order executes virtual trades over time for a long-term order. That distinction matters when translating a schedule into an on-chain execution.

In a conventional scheduled TWAP, the count refers to portions submitted at regular intervals. In a TWAMM, the order is handled as virtual trades over its duration, rather than as the same number of separately submitted swaps. So a plan described as “24 slices” can still help express the intended pace, but it does not mean the mechanism must send 24 individual swaps.

For a large crypto trade, use the count to reason about size, pace, and liquidity—not as a stand-alone setting that guarantees a better result. Compare the proposed per-slice value with pool liquidity, calculate the interval, and account for the costs of the execution approach. A longer duration can also change the interval for the same count, so duration and count should be assessed together.

Related questions

How long should a TWAP order run?

A TWAP order should run for a duration that makes its slice size and interval workable for the trade. With the count fixed, a longer duration spaces portions farther apart; with the duration fixed, adding slices makes them smaller and more frequent. Choose the duration alongside liquidity and execution costs, then recalculate both quantities.

What is a TWAP slice?

A TWAP slice is one portion of a target order, scheduled as part of a series of trades at regular intervals. Its value is the total order value divided by the slice count. For a TWAMM order, treat that count as a pacing model: virtual trades execute over time rather than as that many separate swaps.

For the next decision, start with the smallest per-slice value that fits your liquidity and impact tolerance, then check whether the resulting count, interval, and execution costs work for the order.
